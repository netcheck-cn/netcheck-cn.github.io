DNS 解析失败怎么办？

网站打不开时如何依次检查域名拼写、DNS记录、NXDOMAIN与SERVFAIL等常见问题。

先看是哪一步出了问题

如果聊天软件还能使用，唯独某个网址提示“找不到服务器”，先别急着重启路由器或更换 DNS。把网址里的域名单独取出来，例如 https://www.example.com/path 应查询 www.example.com，不要带协议和路径。

  1. 在DNS 解析查询里先查 A，再查 AAAA。A 对应 IPv4 地址，AAAA 对应 IPv6 地址。
  2. 如果返回地址，DNS 至少在当前公共解析器视角下有结果；继续核查网页 HTTPS 连接，而不是不停更换 DNS。
  3. 如果提示 NXDOMAIN，先检查拼写以及查询的完整主机名；如果是 SERVFAIL，则检查是否为暂时性解析故障。

对照系统查询结果

Windows 打开命令提示符，输入 nslookup example.com。macOS 或 Linux 如果安装了 dig，可使用 dig example.com A。把示例域名换成真正出现故障的域名。

注意：本站显示的是 Google 或 Cloudflare 公共解析器的结果，而系统命令默认使用设备当前配置的解析器。两边结果不同，首先比较查询的域名、记录类型和 DNS 服务，不能马上判断为 DNS 劫持。

常见状态应该怎么理解？

  • NOERROR，但没有 A 记录：不等于域名不存在。它可能只有 AAAA、MX 或其他记录；也可能返回 CNAME，需要继续看目标名称。
  • NXDOMAIN：解析器报告所查询的域名不存在。先检查拼写、主机名前缀，以及是否近期调整过配置。
  • SERVFAIL：解析未能正常完成，可能涉及上游异常或 DNSSEC 验证；换另一家公共解析器对照，必要时联系域名或 DNS 服务商。
  • 请求超时：这代表浏览器未拿到该 DoH 服务的结果，不能直接推断目标域名本身有问题。

解析正常，网页还是打不开？

这时优先检查网址是否使用了正确的 HTTPS 地址、目标服务器是否正常、证书是否异常，以及当前网络是否能连接目标站点。DNS 只能告诉你解析器返回了什么，不能证明网页服务健康。

更深入的状态码定义可参考 RFC 1035；公共解析器的接口说明可查看 Google Public DNS 文档。
